# BookBuddy — Smart Book Discovery System

A college project demonstrating meaningful use of MongoDB Atlas for a real-world
application. Built for the *Intelligent NoSQL Databases* subject.

---

## Problem Statement

Libraries and online platforms hold thousands of books, but discovering a suitable
book based on personal preferences is difficult. Traditional search engines require
users to know exactly what they are looking for. BookBuddy solves this by providing
search, filtering, and simple rule-based recommendations powered by MongoDB Atlas.

---

## Objectives

1. Store and manage book records in a cloud NoSQL database (MongoDB Atlas).
2. Allow users to search and filter books by title, author, genre, and rating.
3. Recommend similar books using transparent, explainable rules.
4. Demonstrate MongoDB CRUD operations, aggregation pipelines, and indexing.
5. Provide a polished, usable web interface using Streamlit.

## Database Schema

Each document in `bookbuddy.books` follows this structure:

```json
{
  "_id":         "ObjectId (auto-generated by MongoDB)",
  "title":       "The Great Gatsby",
  "author":      "F. Scott Fitzgerald",
  "genre":       "English Fiction",
  "rating":      4.36,
  "year":        1925,
  "tags":        ["F. Scott Fitzgerald"],
  "cover_url":   "https://...",
  "description": null
}
```

Fields `description` and `cover_url` are nullable. All other fields are populated
from the dataset where available.

## Installation

### 1. Clone or create the project folder

```powershell
cd "F:\MongoDB Project"
```

### 2. Activate virtual environment

```powershell
.\.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 4. Configure .env

Copy `.env.example` to `.env` and fill in your Atlas connection string:

```
MONGODB_URI="mongodb+srv://bookbuddy_user:<password>@cluster0.xxxxx.mongodb.net/"
```

## How to Import the Dataset

```powershell
# Full import (~10,000 records)
python import_data.py

# Import first 500 records only (faster demo)
python import_data.py --limit 500

# Preview without writing to DB
python import_data.py --dry-run
```

The script downloads the CSV automatically, cleans it, and upserts records.
Running it again is safe — it will not create duplicates.

## Limitations

- Genre is derived from `language_code`, not an actual genre field in the dataset.
- Descriptions are not available in the goodbooks-10k dataset.
- Recommendations use rule-matching, not collaborative filtering.
- The app does not have user authentication.
- Performance measurements on Atlas free tier may not show index benefits at small scale.

## Viva Questions and Answers

**1. What is MongoDB and why did you use it?**  
MongoDB is a NoSQL document database that stores data as JSON-like documents.
I used it because books have optional fields (some have descriptions, some do not),
which fits MongoDB's flexible schema better than a rigid SQL table.

**2. What is a document in MongoDB?**  
A document is a JSON-like record stored in a collection. Each book in BookBuddy
is one document with fields like title, author, genre, and rating.

**3. What is a collection?**  
A collection is a group of documents, similar to a table in SQL. BookBuddy uses
one collection called `books` inside the `bookbuddy` database.

**4. What is PyMongo?**  
PyMongo is the official Python driver for MongoDB. It allows Python code to
connect to Atlas, insert documents, run queries, and execute aggregations.

**5. How do you prevent duplicate records?**  
A unique compound index on `(title, author)` ensures no two documents can have
the same title and author pair. The import script uses `upsert=True` with
`$setOnInsert` so existing records are not overwritten on re-import.

**6. What is an aggregation pipeline?**  
A pipeline is a sequence of stages that process documents on the MongoDB server.
In BookBuddy, `$group` calculates books-per-genre and average ratings without
loading all records into Python.

**7. What is an index and why does it matter?**  
An index is a data structure that lets MongoDB find documents faster, like an
index in a book. Without an index, MongoDB reads every document (COLLSCAN).
With an index, it jumps directly to matches (IXSCAN).

**8. What is the difference between `find` and `aggregate`?**  
`find` retrieves documents matching a filter. `aggregate` transforms and
summarises documents using a pipeline of operations like `$group`, `$sort`,
and `$match`.

**9. What is `$set` in an update operation?**  
`$set` replaces the value of a specific field without affecting other fields.
For example, `{"$set": {"rating": 4.5}}` updates only the rating.

**10. How do recommendations work in BookBuddy?**  
BookBuddy uses three simple rules: first it looks for books with the same genre,
then books by the same author, then books sharing tags. No machine learning is
used. Each recommendation shows exactly why it was suggested.

**11. What is Atlas?**  
MongoDB Atlas is the official cloud-hosted MongoDB service. It provides a
free tier, automatic backups, and a web interface for managing databases.

**12. How are credentials stored securely?**  
The Atlas connection string is stored in a `.env` file that is excluded from
Git via `.gitignore`. The application reads it using `python-dotenv`. The
password never appears in source code or logs.

**13. What is `explain()` in MongoDB?**  
`explain()` returns information about how MongoDB executed a query, including
whether it used an index, how many documents it examined, and how long it took.

**14. What is a `text index` and how is it used here?**  
A text index enables full-text search across string fields. BookBuddy creates
one on `title` and `author` fields to support keyword-based searching.

**15. What are the limitations of this project?**  
Genre is derived from language code, not actual genre data. Recommendations
are rule-based and do not learn from user behaviour. There is no authentication
or personalisation. Performance improvements from indexing are not dramatic at
this scale because Atlas free-tier datasets are small.
